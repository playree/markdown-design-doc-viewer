# デスクトップアプリ

[English](desktop.md) | 日本語

[Markdown 設計書ビューア](../README.ja.md)のプレビューを、Windows・macOS・Linux のデスクトップアプリにしたものです。VS Code がなくても設計書を読めます。表示は拡張機能のプレビューと同じで、**mermaid のシーケンス図・フローチャートと処理概要の横並び**、矢印（ノード）と見出しの相互ハイライト、紐付け漏れの警告、目次、図・画像の拡大表示、表のヘッダ行の固定に対応します。

アプリはビューアです。設計書はエディタで編集し、保存するたびにアプリの表示が更新されます。

## インストール

[デスクトップアプリのリリース](https://github.com/playree/markdown-design-doc-viewer/releases?q=desktop&expanded=true)（タグ `desktop-vX.Y.Z`。Pre-release と付いたものはリリース候補です）の最新のものから、お使いの OS のインストーラをダウンロードします。

| OS | ファイル |
| --- | --- |
| Windows | `Markdown.Design.Doc.Viewer_<バージョン>_x64-setup.exe`（または `.msi`） |
| macOS（Apple シリコン） | `Markdown.Design.Doc.Viewer_<バージョン>_aarch64.dmg` |
| macOS（Intel） | `Markdown.Design.Doc.Viewer_<バージョン>_x64.dmg` |
| Linux | `.deb`（Debian・Ubuntu）、`.rpm`（Fedora など）または `.AppImage` |

アプリのバージョンは、拡張機能・コマンドラインとは別です。変更点は[変更履歴](../desktop/CHANGELOG.md)（英語）にあります。

### 署名がないことによる警告

インストーラにはまだ署名がないため、初回に OS が警告を出します。

- **Windows**: SmartScreen の「Windows によって PC が保護されました」が出たら、**詳細情報** → **実行** を押します。
- **macOS**: 「悪質なソフトウェアかどうかを Apple で確認できないため、開けません」（または「壊れているため開けません」）と出たら、**システム設定** > **プライバシーとセキュリティ** を開き、アプリについてのメッセージの横の **このまま開く** を押します。ボタンが出ない場合は、ターミナルで隔離属性を外します。

  ```sh
  xattr -dr com.apple.quarantine "/Applications/Markdown Design Doc Viewer.app"
  ```

- **Linux**: AppImage には実行権限を付けます（`chmod +x Markdown*.AppImage`）。`.deb`・`.rpm` では、アプリに必要な WebKitGTK 4.1（`libwebkit2gtk-4.1-0` / `webkit2gtk4.1`）がパッケージマネージャで入ります。

## 使い方

Markdown ファイル（`.md`、`.markdown`）を次のどれかで開きます。

- **ファイル** > **開く...**（Ctrl+O、macOS では ⌘O）、またはファイルを開いていないときに出るボタン
- ウィンドウへのドラッグ&ドロップ
- ファイルマネージャ: エクスプローラー（Windows）・Finder（macOS）でファイルを右クリックし、**プログラムから開く**（macOS では **このアプリケーションで開く**）> **Markdown Design Doc Viewer**。Linux ではファイルマネージャの **別のアプリケーションで開く**
- コマンドライン: `markdown-design-doc-viewer docs/login.md`（Windows ではインストール先の `markdown-design-doc-viewer.exe`）
- **ファイル** > **最近開いたファイル**、またはファイルを開いていないときに出る一覧

インストーラは、アプリを `.md`・`.markdown` を開けるアプリに加えます（既定のアプリにはしません）。ダブルクリックでアプリで開くには、既定のアプリにします: **プログラムから開く** > **別のプログラムを選択** で **常に使う**（Windows）、**情報を見る** > **このアプリケーションで開く** > **すべてを変更...**（macOS）、ファイルのプロパティ（Linux）。AppImage は（インストールしないので）加えられません。

アプリの起動中にファイルマネージャやコマンドラインからファイルを開くと、新しいウィンドウで開きます。そのファイルを表示しているウィンドウがあれば、そのウィンドウを前面に出します。ファイルを表示していないウィンドウがあれば、そこで開きます。**ファイル** > **開く...**、ドラッグ&ドロップ、リンクでは、そのウィンドウで開きます。**ファイル** > **閉じる**（Ctrl+W、⌘W）でウィンドウを閉じ、最後のウィンドウを閉じるとアプリが終了します。**ファイル** > **終了**（macOS ではアプリのメニューの **終了**）ですべてのウィンドウを閉じます。

**ファイル** > **最近開いたファイル** と、ファイルを開いていないときの画面に、最近開いたファイルを新しい順に 10 件まで並べます（すべてのウィンドウで共通で、次の起動でも残ります）。並べるのは、開くダイアログ・ドラッグ&ドロップ・ファイルマネージャ・コマンドライン・この一覧から開いたファイルです。サイドバーやリンクで開いたファイルは並べません。見つからなくなったファイル（削除・移動したもの）を選ぶと、開けないことを表示して一覧から除きます。**ファイル** > **最近開いたファイル** > **一覧を消去**、または画面の **消去** で一覧を空にします。

ファイルが保存されると、スクロール位置を保ったまま表示を更新します。**ファイル** > **再読み込み**（Ctrl+R、⌘R）でも読み直せます。

**表示** > **サイドバー**（Ctrl+B、⌘B）で、サイドバーを表示・非表示にします。**ファイル一覧** タブにはフォルダの Markdown ファイルをサブフォルダも含めて木構造で並べ、**履歴** タブには設計書の Git の履歴を並べます。

- 表示するかどうかと幅（右端のドラッグで変えられます）は、次の起動に引き継がれます。
- 並べるフォルダ:
  - 開いた設計書のフォルダです。そのフォルダの中の設計書を開いている間は、フォルダを変えません。
  - **ファイル** > **フォルダを開く...**、サイドバーのフォルダのボタン、またはフォルダをウィンドウにドロップして、ほかのフォルダを選ぶこともできます。
- ファイルを選ぶと、そのウィンドウで開きます。
- ファイル・フォルダの追加・削除・名前の変更は、サイドバーにすぐ反映されます。
- 次のものは並べません。
  - 隠しファイル・隠しフォルダ（`.git` など、名前が `.` で始まるもの）
  - `node_modules`
  - Markdown ファイルを含まないフォルダ
- サイドバーを表示している間は、ウィンドウの幅からサイドバーの幅を除いた幅で、図と処理概要を横並びにするかを決めます。

**履歴** タブでは、拡張機能の **設計書を Git の履歴と比較** と同じように、設計書を Git の履歴と比較できます。

- 設計書を変更したコミットを、新しい順に件名・短いハッシュ・作者・日時とともに並べます（名前の変更も追います）。
- コミットを選ぶと、そのコミットとの差分をプレビューに表示します。追加・変更・削除したブロックに緑・青・赤の帯を付け、変更したブロックでは変わった語を強調し、変更した図には変更前の図を折りたたんで添えます。下部のバーで前後の変更へ移動できます。
- 同じコミットをもう一度選ぶか、下部のバーを閉じると、通常の表示に戻ります。別の設計書を開いたときも戻ります。
- 差分は、ファイルを保存すると更新します。
- 履歴は、タブを表示したとき、別の設計書を開いたとき、**ファイル** > **再読み込み**、タブの再読み込みボタンで読み込みます。タブを表示するまで Git は実行しません。
- PATH にある Git が必要です。macOS では Homebrew の Git（`/opt/homebrew/bin/git` または `/usr/local/bin/git`）を優先し、なければ Command Line Tools の Git を使います（入っていなければ OS がインストールを勧めます）。Git が見つからないときや、設計書が Git リポジトリの中にないときは、タブにそのことを表示します。

タブの履歴の上には設計書のリポジトリのブランチを表示し、ターミナルを使わずに別のブランチへ切り替えたり、最新のコミットを pull したりできます。

- 一覧には、ローカルのブランチと、まだローカルにないリモートのブランチ（`origin/feature` など。グループにまとめます）を並べます。HEAD が切り離されているときは、そのことを表示します。
- 別のブランチを選ぶと、確認してからリポジトリをそのブランチに切り替えます（`git switch`）。リモートのブランチを選ぶと、それを追跡するローカルのブランチを作ります（`git switch --track`）。切り替えると、設計書・**ファイル一覧** タブ・履歴をそのブランチの内容で表示し直し、コミットとの比較は終わります。切り替えたブランチに設計書がないときは、プレビューにそのことを表示します（ターミナルや別のウィンドウで切り替えたときも同じです）。元のブランチに戻すと、また表示します。
- pull ボタンは、確認せずにすぐ pull します。fast-forward できるときだけ取り込み（`git pull --ff-only`）、取り込んだか、すでに最新だったかを表示します。コミットとの比較は続けます。
- Git が失敗したときは、その理由をダイアログで表示し、リポジトリはそのままにします。たとえば、コミットしていない変更が上書きされるとき、リモートにないコミットがブランチにあるとき（分岐しているとき）、上流のブランチがないときです。
- Git はユーザー名・パスワード・パスフレーズをターミナルで尋ねません。それらが要るリモートからの pull は、認証情報ヘルパー（Git Credential Manager などのサインインの画面が開くことがあります）や ssh エージェントがあればできます。なければ失敗します。2 分を超える pull は打ち切ります。
- ブランチは履歴と一緒に読み込みます。ほかで作ったブランチを一覧に出すには、再読み込みボタンを使ってください。設計書がなかったブランチからほかで切り替えて戻したときは、**ファイル** > **再読み込み** で表示します。

**表示** > **設計書一覧**（Ctrl+Shift+D、⌘⇧D）で、拡張機能の **設計書一覧を開く** と同じように、サイドバーのフォルダとそのサブフォルダの設計書（front matter に `type: design_doc`）の一覧を設計書の代わりに表示します。

- フォルダごとの表に、タイトル・ファイル名・`version`・`product`・`status`・`updated` を載せます。検索欄で絞り込め（タイトル・ファイル名・メタ情報が対象）、列見出しをクリックするとその列で並べ替えます。
- タイトルをクリックすると、その設計書を開きます。一覧に戻るには、もう一度メニューを使います。
- まだフォルダがなければ、フォルダを選ぶダイアログを出します。
- サイドバーに並べないファイルは、一覧にも載せません。
- サイドバーを表示している間はファイルの追加・削除・名前の変更で、また **ファイル** > **再読み込み** で一覧を読み直します。ファイルの内容の変更（`status` の書き換えなど）は **ファイル** > **再読み込み** で反映します。

リンク:

- `#見出し` はその見出しへスクロールします。
- 別の Markdown ファイルへのリンクは、同じウィンドウで開きます（`#フラグメント` があればその見出しへ）。
- `http:`・`https:`・`mailto:` のリンクは、既定のブラウザやメールアプリで開きます。
- その他のファイルは、画像・PDF・テキスト・CSV・JSON・YAML・Office のファイルなら既定のアプリで開きます。それ以外（プログラムやスクリプトなど）は実行せず、フォルダで表示します。

画像は設計書のフォルダから探します。先頭が `/` のパスも設計書のフォルダが基準です（VS Code のようなワークスペースがないため）。

**ファイル** > **HTML にエクスポート...** で、表示中の設計書を 1 つの HTML ファイルに保存します（保存先はダイアログで選びます）。拡張機能の **Export Design Doc as HTML** と同じ HTML で、図はライトテーマで描画し、ブラウザでも横並びと矢印 ⇔ 見出しのハイライトが動きます。設計書のフォルダ（とその下）の画像は HTML に埋め込み、それ以外の画像は保存先からの相対パスでリンクします。保存後は **ブラウザで開く** で表示できます。

**表示** > **テーマ** で、OS の配色（ライト・ダーク。切り替えに追従します）か、常にライト・ダークで表示するかを選べます。メニューや文言は、OS の言語が日本語なら日本語、それ以外は英語で表示します。

拡張機能との違い: エディタとの連動（スクロールの同期、ダブルクリックで行へ移動）はありません。設定は拡張機能の既定値です。複数の設計書をまとめてエクスポートするには[コマンドライン](cli.ja.md)を使ってください。

## 開発

アプリは [desktop/](../desktop/) にあります。拡張機能の webview（webview/main.ts）を、拡張ホストの代わりの TypeScript のホストと組み合わせて動かし、Rust の [Tauri 2](https://tauri.app/) のアプリ（[desktop/src-tauri/](../desktop/src-tauri/)）はファイルの読み込み・監視とリンクを開く処理だけを行います。

Node.js と pnpm のほかに次が必要です。

- [Rust](https://rustup.rs/)（stable）
- Windows: Visual Studio Build Tools（「C++ によるデスクトップ開発」）と WebView2（Windows 10・11 には入っています）
- macOS: Xcode Command Line Tools（`xcode-select --install`）
- Linux（Debian・Ubuntu）: `sudo apt install build-essential file libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev libxdo-dev libssl-dev patchelf`

```sh
pnpm install
pnpm desktop:dev -- -- /absolute/path/to/doc.md   # ビルドしてアプリを起動する（ファイルは省略可。アプリは desktop/src-tauri で動くので絶対パスで渡す）
pnpm desktop:bundle                               # インストーラを desktop/src-tauri/target/release/bundle/ に作る
```

`pnpm desktop:build` は Web 側（desktop/dist/）だけをビルドします（上の 2 つのコマンドは最初にこれを実行します）。Rust の依存（Cargo.lock）を変えたら、`pnpm desktop:licenses` でそのライセンスを desktop/src-tauri/ThirdPartyLicenses.txt に書き出してください（インストーラに入ります。[cargo-about](https://github.com/EmbarkStudios/cargo-about) が要ります: `cargo install cargo-about --version 0.9.2 --locked --features cli`。CI が検査に使うのと同じバージョンです）。アプリの動作確認は画面のある環境で行ってください。CI での Windows・macOS・Linux のビルドは時間がかかるので、手動で実行したときだけ動きます（[desktop.yml](../.github/workflows/desktop.yml)）。desktop/src-tauri・Tauri の設定・依存を変えたときと、リリースの前に実行してください。
