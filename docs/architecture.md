# アーキテクチャ

3 つのバンドルに分かれ、[esbuild.mjs](../esbuild.mjs) でそれぞれビルドされる（設定は [scripts/build-options.mjs](../scripts/build-options.mjs)）。デスクトップアプリ（4 つ目）は `--desktop` のときだけ、埋め込みのビューア（5 つ目）は `--embed` のときだけ、それだけをビルドする。

- **拡張ホスト**（`src/extension/extension.ts` → `dist/extension.js`, Node/CJS）: Markdown を HTML に変換して webview に送る。
- **webview**（`webview/main.ts` → `dist/webview.js`, ブラウザ/IIFE。埋め込みのビューアの embed/ も同じ preview.ts を使う）: HTML のサニタイズ、mermaid 描画、ハイライト・スクロール同期などの UI。本体は [webview/preview.ts](../webview/preview.ts) の `createPreview(ctx)` で、main.ts は body・window のスクロール・`acquireVsCodeApi`・window の message をコンテキストにして渡すエントリで、`createPreview` と message のリスナーの登録の後に `ready` を送る（拡張ホスト（src/extension/previewPanel.ts）とデスクトップアプリ（desktop/host.ts）は `ready` を受け取るまで `update` を送らないので、消さないこと）。エクスポートした HTML に埋め込むスクリプトは `webview/export.ts` → `dist/export.js`。
- **CLI**（`src/cli/cli.ts` → `dist/cli.js`, Node/CJS）: HTML エクスポートのコマンドライン版。`vscode` を external にしていないので、vscode に依存するモジュールを import するとビルドが失敗する。`capture` コマンド（[src/cli/capture.ts](../src/cli/capture.ts)）は動いている Web アプリの画面をヘッドレス Chrome で開き、ワイヤーフレームの HTML に書き出す。ページの中で動く処理（[src/cli/capturePage.ts](../src/cli/capturePage.ts)）と [src/cli/captureCss.ts](../src/cli/captureCss.ts) の一部の関数はソースの文字列としてページに渡すので、関数の外のものを参照しないこと。
- **デスクトップアプリ**（`desktop/main.ts` → `desktop/dist/app.js`, ブラウザ/IIFE。Tauri 2）: 拡張の webview（`webview/main.ts`）をそのまま載せる。[desktop/vscodeShim.ts](../desktop/vscodeShim.ts) が `acquireVsCodeApi` のスタブ（state は localStorage）と翻訳した body の data 属性を用意し、[desktop/host.ts](../desktop/host.ts) が拡張ホストの代わりに `renderDocument` で HTML にして `update` を送る（設定は表示 > 設定... の設定ページ（[desktop/settingsDialog.ts](../desktop/settingsDialog.ts)。モーダルの `<dialog>`）で変え、[desktop/settings.ts](../desktop/settings.ts) が localStorage の値を検証する。`syncEditor` は false、`theme` は常に `auto` で、配色は body の `vscode-light` / `vscode-dark` クラスで切り替え、[webview/theme.css](../webview/theme.css)（埋め込みのビューアと共有）がその変数を定義する。ウィンドウの背景などデスクトップだけのものは [desktop/theme.css](../desktop/theme.css)）。メニュー・D&D・開くダイアログも host.ts。フォルダの Markdown を木構造で並べるサイドバー（表示 > サイドバー）は [desktop/sidebar.ts](../desktop/sidebar.ts)（DOM）と [desktop/folderTree.ts](../desktop/folderTree.ts)（並べ替えなどの純粋な関数）で、body の左に固定し、body の `data-seqnotes-inset-left` にその幅を書いて webview の横並びの判定から除かせる（VS Code・エクスポートでは付かない）。パスの処理は [desktop/paths.ts](../desktop/paths.ts)（Windows のパスも扱う純粋なモジュール）。Rust 側（[desktop/src-tauri/src/lib.rs](../desktop/src-tauri/src/lib.rs)）は薄い層で、ファイルの読み込み（`open_document`）、親フォルダの監視（`document-changed`、rename `path` だけで、直前の `git_log` が返した `(hash, path)` の組に含まれるものだけを受け付ける）だけを行う。webview には fs・opener の権限を与えない（capabilities/default.json）。HTML エクスポート（ファイル > HTML にエクスポート...）は拡張と同じく `renderForExport` → webview の `export` メッセージ → `exportPage` で組み立て、エクスポートしたページに入れる `export.js`・`webview.css`・`export.css` は desktop/dist にもビルドして `fetch` で読む。プロセスは single-instance プラグインで 1 つにし、起動中に渡されたファイル（Windows・Linux は 2 src/ は機能ごとのフォルダに分ける: `extension/`（拡張ホスト。`vscode` を import してよいのはここだけ）、`cli/`（CLI・`capture`・ヘッドレス Chrome）、`export/`（HTML エクスポートと設計書一覧の共通部分）、`git/`（git の実行と出力の解析）、`diff/`（差分の計算と描画）、`authoring/`（警告の収集・クイックフィックス・補完の純粋な部分）、`markdown/`（変換パイプライン・表・ワイヤーフレーム）、`diagrams/`（各図のパーサと文言）、`shared/`（メッセージ型・翻訳・slug）。webview・desktop・embed は `extension/`・`cli/` 以外から import する（Node 依存は `cli/`・`extension/` と `git/gitCli.ts` だけ）。テスト（test/）はフォルダに分けない。

HTML エクスポートは、vscode 非依存の共通部分（画像の解決、タイトル、ページの組み立て）が [src/export/exportPage.ts](../src/export/exportPage.ts) にあり、VS Code のコマンド（[src/extension/exportHtml.ts](../src/extension/exportHtml.ts)）と CLI が使う。図の描画はどちらも webview の `exportBody`（`export` メッセージ）で、VS Code ではプレビューの webview、CLI では [src/cli/headless.ts](../src/cli/headless.ts) がヘッドレス Chrome に `dist/webview.js` を載せて行う（`pnpm screenshots` も同じ Chrome の探し方を使う）。

webview は `src/shared/protocol.ts`（メッセージ型）、`src/markdown/render.ts`（`DiagramMeta` 型）、`src/diagrams/sequence.ts`（`normalizeLabel`）、`src/shared/slug.ts`、`src/markdown/wireframe.ts`（`partNumber`。`src/markdown/tables.ts`・`src/shared/l10n.ts` も一緒に入る）を import する。これらに `vscode` や Node 依存を持ち込まないこと。

## 変換パイプライン（拡張ホスト側）

1. `PreviewManager`/`Preview`（[src/extension/previewPanel.ts](../src/extension/previewPanel.ts)）がドキュメント変更・設定変更を受けて `renderDocument` を呼び、`update` メッセージで HTML を送る。エディタのスクロール・カーソルは `scrollToLine` / `markLine` で送る。
2. [src/markdown/render.ts](../src/markdown/render.ts) の markdown-it プラグインが、見出しに `sn-` 接頭辞付きの一意な id（DOMPurify の DOM clobbering 対策で接頭辞が必要）、各ブロックに `data-line` を付ける。mermaid のフェンスは `<pre>` のまま出力し、図の情報を `data-seqnotes-meta` に JSON で埋め込む（描画は webview 側）。
3. [src/markdown/linker.ts](../src/markdown/linker.ts) の `linkDiagrams` がトークン列からシーケンス図・フローチャート・ER 図・状態遷移図（`DiagramInfo.kind`）を探し、`%% @link-headings` 付きかつトップレベル（level 0）の図だけを横並び対象（`paired`）にする。右カラムの範囲（`<!-- link-headings:end -->`／次の `@link-headings` 付きの図／文書末尾まで）の見出しと、矢印・ノードの文言または `%% @ref` を照合する（フローチャート・ER 図・状態遷移図のノードも `messages` に入る）。解決できない場合は warning を返す。図の種類ごとの文言（警告・印・診断・補完）は [src/diagrams/diagramWording.ts](../src/diagrams/diagramWording.ts) にまとめる。横向き（LR/RL）の図は `stacked` で、常に縦並びにする（`.seqnotes-pair-stacked`）。
4. `renderDocument` がトークン列をスライスし、`paired` な図を `.seqnotes-pair > .seqnotes-seq-col + .seqnotes-overview-col` で包んで出力する。warning はプレビュー上部に置く。スクロール同期は `data-line` が文書順に並んでいる前提なので、warning には `data-line` ではなく `data-seqnotes-jump` を付ける。

ワイヤーフレーム（[src/markdown/wireframe.ts](../src/markdown/wireframe.ts)）は、ローカルの HTML ファイルの画像・リンク（またはリンクの中の画像）だけの段落を `wireframe` トークンにし、直前の `<!-- wireframe: … -->` のオプションを読む。ファイルはホストが読み（`loadWireframes`。VS Code は [src/extension/documentFiles.ts](../src/extension/documentFiles.ts) で、プレビューと診断は HTML・CSS の変更に追従する。プレビューと診断は `DocumentAnalyzer` を共有し、文書の版ごとの parse とワイヤーフレームの読み込みを 1 回にする（診断はそのトークンを `issuesOf` で読むだけで、描画はトークンを書き換えるのでプレビューは自分で parse する。キャッシュの純粋な部分は [src/extension/documentCache.ts](../src/extension/documentCache.ts)）。CLI は fs、デスクトップは `read_wireframe`）、`RenderEnv.wireframes` で渡す。`linkDiagrams` はそれを `kind: 'wireframe'` の図として、パーツ（`data-item` の番号ごと）を同じ番号の見出し（または `data-ref` の見出し）と、項目の表（表のオプション `item=`）の行に紐付ける（行だけに紐付くパーツは `seqnotes-part-…` の target を持ち、行の `data-seqnotes-section` にも同じ値を付ける）。webview（[webview/wireframe.ts](../webview/wireframe.ts)）は HTML を DOMPurify でサニタイズして Shadow DOM に表示し、各パーツの上に紐付け用の枠（`.seqnotes-part`、番号付き）を重ねる。エクスポートでは、`<pre>` に残したサニタイズ済みの HTML から export.ts が表示し直す。

[src/diagrams/sequence.ts](../src/diagrams/sequence.ts) は mermaid 文法の最小限のパーサで、矢印（メッセージ）の描画順、行番号、`@ref`、`@link-headings` だけを抽出する。[src/diagrams/flowchart.ts](../src/diagrams/flowchart.ts) はフローチャート版で、ノードの ID・ラベル・行番号、`@ref`、`@link-headings`、方向だけを抽出する。[src/diagrams/erDiagram.ts](../src/diagrams/erDiagram.ts)（エンティティ）と [src/diagrams/stateDiagram.ts](../src/diagrams/stateDiagram.ts)（状態）も同じで、`@ref`・マーカーの処理と行ごとのノードの集計は [src/diagrams/diagramNodes.ts](../src/diagrams/diagramNodes.ts) の `readNodes` を共有する。

## webview 側

- プレビューは、ページ全体ではなくコンテキスト（[webview/viewerContext.ts](../webview/viewerContext.ts) の `ViewerContext`）の中で動く: ビューアの要素 `el`（クラス `seqnotes-wide` などとテーマ・翻訳した文言の data 属性を読み書きし、目次・差分バー・脚注のポップアップ・ズームの overlay を入れる。ページでは body）、描画先 `root`、スクロールの抽象 `ScrollHost`（ページでは window、埋め込みでは要素がスクロールする `elementScrollHost`）、要素の id の接頭辞 `idPrefix`（mermaid の SVG の id など。ページでは `seqnotes`）、ホストへのメッセージと state。ほかのビューアと同じページに置けるように、preview.ts と共有のモジュール（linking・toc・diffBar・footnotePopup・diff・tableTree）は `window` のスクロール・`document.body`・`document.getElementById` を直接使わない（要素を見えるところへスクロールするのも、埋め込みでホストのページまでスクロールしないように `scrollIntoView` ではなく `ScrollHost.reveal`。id は `root` の中から linking.ts の `elementById` で探す。mermaid が図を測るための要素も、body ではなくビューアの要素の中の見えない `.seqnotes-mermaid-scratch` に作らせる）。mermaid の設定はグローバルなので、描画の順番待ち（`renderQueue`）は全ビューアで共有する。`createPreview` が返す `destroy` は、overlay とリスナーを外す。
- CSS（webview/preview.css・export.css）は、`body` ではなくクラス `.seqnotes-viewer`（ページでは body に付ける。描画先には `.seqnotes-viewer-root`）に書き、Markdown の要素（`h1`・`a`・`table` など）のルールは詳細度を変えないように `:where(.seqnotes-viewer) …` にする（例外は、ページ全体の背景・スクロールバーの色を決める `html:has(> body…)`）。ページの shell（src/extension/previewPanel.ts・src/cli/headless.ts・src/export/exportPage.ts・desktop/index.html・scripts/screenshots.ts）の body にはこのクラスを付ける。

- `DOMPurify.sanitize` → `mermaid.render`（テーマとソースをキーに SVG をキャッシュ）→ `annotateMessages` の順に処理する。`annotateMessages` は SVG 内のメッセージ要素を、パーサの結果と描画順で対応付ける。数が合わないときだけラベル一致で対応付けるので、`sequence.ts` のメッセージ抽出は mermaid の解釈と件数・順序が一致している必要がある。フローチャート・ER 図・状態遷移図は `annotateNodes` がノード ID（`data-id`、なければ要素 id `<svg id>-flowchart-<ノード ID>-<n>`。ER 図は `entity-<名前>-<n>`、状態遷移図は `state-<ID>-<n>` で、複合状態は `g.statediagram-cluster` の `data-id`）で対応付ける。
- 横並びにするかはビューアの幅（ページではウィンドウ幅。`mdDesignDoc.splitMinWidth`）で決まり、ビューアの要素の `seqnotes-wide` クラスで切り替える。カラム幅はドラッグで変えられ（`--seqnotes-split` をビューアの要素に書く）、state（VS Code では `vscode.setState`）に保存される。
